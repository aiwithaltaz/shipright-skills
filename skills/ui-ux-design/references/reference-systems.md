# Reference systems for a new system

Load only when creating a new system. An existing app reuses its observed system. Do not browse these for a small correction.
Pick at most two or three. Borrow a named property only, such as spacing rhythm, table density or form layout. Never borrow identity, color, type or icons as a skin.
Skip a system when Component Gallery marks it unmaintained or as having accessibility issues. Popularity is not a reason to adopt it.
Credit and limits for Component Gallery by Iain Bean live in design-system-sources.md. Do not copy Gallery definitions, guidance, code or screenshots.

## Dashboards and operator tools

Carbon, Atlassian, Primer, PatternFly, Polaris.
Useful properties: dense tables, form layout, status that sits with the record, and a quiet page chrome.
Do not import the vendor brand.

- Carbon: https://carbondesignsystem.com/
- Atlassian: https://atlassian.design/
- Primer: https://primer.style/
- PatternFly: https://www.patternfly.org/
- Polaris: https://polaris.shopify.com/

## Clean product UI

Geist, shadcn/ui, Radix.
Useful properties: restrained type, one primary action, and accessible unnamed primitives where the project already uses them.
Do not treat a component kit as the product's design system.

- Geist: https://vercel.com/geist
- shadcn/ui: https://ui.shadcn.com/
- Radix: https://www.radix-ui.com/

## Forms and public services

GOV.UK, NHS, USWDS.
Useful properties: one question group at a time, visible labels, and plain language for errors.
Do not copy government identity onto a different kind of product.

- GOV.UK: https://design-system.service.gov.uk/
- NHS: https://service-manual.nhs.uk/
- USWDS: https://designsystem.digital.gov/

Record each borrowed property, why it serves this job, and what must not carry over. Mark the result Proposed until the user says OK.
