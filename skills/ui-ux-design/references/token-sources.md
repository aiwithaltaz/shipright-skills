# Token sources

Load only for token provenance, interchange or an actual tool/system choice. These are original ShipRight summaries, not copied source text or product-specific approval. Official pages accessed 2026-10-12; no paid material, code library or screenshot collection was copied.

| Credit and source | Apply selectively |
| --- | --- |
| [Design Tokens Community Group, Format 2025.10](https://www.designtokens.org/tr/2025.10/format/), [Resolver](https://www.designtokens.org/tr/2025.10/resolver/) | Learn typed interchange, aliases and conditional value resolution. Distinguish normative format rules from examples. This Community Group report is not a W3C Standard and does not prescribe primitive/semantic/component layers. Do not require DTCG conversion when native tokens already work. |
| [Atlassian Design, tokens explained](https://atlassian.design/tokens/design-tokens/), [use tokens in code](https://atlassian.design/foundations/tokens/use-tokens-in-code/) | Learn role-based reuse and mapping values through themes. Existing Atlassian consumers need their real theme initialization, not just a package name. Do not adopt its palette, names or packages as a universal ShipRight system. |
| [Style Dictionary maintainers, configuration](https://styledictionary.com/reference/config/), [tokens](https://styledictionary.com/info/tokens/) | Learn source-to-target transforms, aliases and emitted references. Verify actual installed version and transformations; generated CSS is not another authoritative source to edit by hand. No mandatory installation. |
| [Tokens Studio team, DTCG versus legacy](https://docs.tokens.studio/manage-settings/token-format), [themes](https://docs.tokens.studio/manage-themes/themes-overview) | Learn format, token-set and theme mapping boundaries. Check actual plugin version, export support and permissions. Its format documentation notes unsupported types; do not equate a format switch with complete interoperability or require paid theme tooling. |
| [Fluent 2 tokens](https://fluent2.microsoft.design/design-tokens), [Carbon themes](https://www.carbondesignsystem.com/building-blocks/foundations/themes/overview) | Existing systems may call primitives global tokens and semantics aliases/roles. Preserve the selected system's names and layering; do not retrofit all systems into one hierarchy. Consult other already-selected systems' original guidance as needed. |
| [Tailwind theme variables](https://tailwindcss.com/docs/theme), [v3 CSS-variable colors](https://v3.tailwindcss.com/docs/customizing-colors#using-css-variables) | Keep mappings compatible with the project's installed major version. These are implementation references, not brand choices or permission to replace configuration. |

Access limits: public readable or indexed official guidance, not a complete source/code audit. Some Atlassian routes return no extracted text, so their indexed official content also informed these summaries. DTCG and vendor docs can differ in version and supported types. Recheck compatibility for actual exports; unavailable details remain Unknown. Preserve older registers, access dates and limitations.
