# Step 2a: Color (before the style pack, write it in PRODUCT.md)

Pick the palette first. The style pack then follows it. Two rules, in this order:

## Rule A: the product already has colors
If there is a logo, a live site, an app, brand files or colors in the brief, read them (CSS variables, logo, screenshots) and adopt them. Write the hex values and where each came from in PRODUCT.md under **Color**. You may add neutrals and state colors around them. Do not replace a working brand.

## Rule B: no colors yet
1. Look at 3 to 5 real competitors in the same market (for a habit app: Streaks, Habitify, Finch, Loop, Way of Life). Write each one's main colors (hex or plain names) and one link in PRODUCT.md.
2. Find what the category shares (calm, warm, soft greens, light backgrounds) and what nobody owns yet.
3. Propose a palette that feels familiar for the category but is its own: background, text, one action color, 3 state colors. Write 2 lines of reasoning.

## Never
- Never reuse a palette from another product made in this session or this folder (check earlier PRODUCT.md / DESIGN.md files you made). Name the past palettes you checked.
- Never default to black with neon (acid lime, electric green, hot magenta). Dark plus neon only when the audience is clearly sport, gaming or nightlife AND Rule A or B points there.
- Never the generic AI set: cream + serif + copper, purple gradients, system blue.

The style pack gives fonts, shapes and details. Swap its colors for this palette.
