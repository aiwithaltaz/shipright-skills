# Step 1b: UX (inside PRODUCT.md, Flows section)

## The real question
Write the one question the audience has in the first 5 seconds. Examples: a hiring manager: "Can this person run my program?"; a habit user: "What do I do today?". The first screen answers it. Everything else is in the order the next questions come.

## Information order
List sections or screens in that order, one line each: what it answers. Proof comes right after the claim it backs.

## Scope at a glance (hard)
The audience's main proof (all programs, all habits, all features) shows together in one overview: a table, list or grid that fits on one or two screens. Any pinned, carousel or one-at-a-time section comes after it as the deep dive, never instead of it. A hiring manager sees every program before reading one.

## Flows
Each job in 3 taps or fewer from where the user is. Records are editable and deletable.

## States
For every screen: empty, loading, failed, long text, big numbers, first visit. Follow the [clarity rules](clarity.md): every state has its own look and a label, plain counts, labeled grids, never color only.

## Redesigns
Keep the current flows that work (from BASELINE.md). Do not remove an interaction unless the table says why.
