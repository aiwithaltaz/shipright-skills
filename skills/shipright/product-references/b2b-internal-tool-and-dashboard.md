# B2B internal tool and dashboard references
Notes only. Use them to pick 2-3 references. These are not rules.

## Linear
https://linear.app/
- Analyst reference target: compact issue hierarchy, restrained application chrome and clear selection states.
- Study the working issue interface, not only its promotional homepage; exact current pixel measurements are unverified.

## Attio
https://attio.com/
- Analyst reference target: CRM record hierarchy, configurable data views and compact relation-rich records.
- Use as a reference for making complex customer data approachable without oversized cards.

## Stripe Dashboard
https://stripe.com/
- Analyst reference target: clear financial formatting, summary-to-detail hierarchy and operational tables.
- Do not copy financial demo metrics into unrelated products.

## Vercel
https://vercel.com/
- Analyst reference target: consistent neutral surfaces, compact project information and clear deployment states.
- Pair product references with Geist typography and component guidance.

## Notion
https://www.notion.com/
- Analyst reference target: content-first workspace, contextual controls and consistent database-view switching.
- Study progressive disclosure rather than copying every hidden-control interaction.

## HubSpot
https://www.hubspot.com/products/crm
- Analyst reference target: CRM object navigation, filters, record-detail hierarchy and business-task organization.
- Use as a functional-completeness reference, not an instruction to reproduce its entire interface density.

## folk
https://www.folk.app/
- Analyst reference target: approachable contact lists, relationship context and view-based organization.
- Compare how a simpler CRM reduces visual and conceptual overhead.

## Twenty
https://twenty.com/
- Analyst reference target: compact CRM records, shared primitives and deliberate text overflow.
- Implementation reuse requires checking AGPL qualifications and exceptions.
- Sources: https://github.com/twentyhq/twenty https://github.com/twentyhq/twenty/blob/main/LICENSE

## Intercom
https://www.intercom.com/
- Analyst reference target: inbox/list/detail relationships, visible conversation state and contextual customer information.
- Use for work queues where the primary job is selecting, investigating and acting.

## GitHub
https://github.com/
- Analyst reference target: dense issue and pull-request lists, clear status semantics and restrained action hierarchy.
- Use its public interface as a directly inspectable reference for data-rich work.

## Sentry
https://sentry.io/
- Analyst reference target: actionable issue lists, severity context and summary-to-investigation flows.
- Borrow the relationship between overview metrics and underlying work, not arbitrary chart counts.

## PostHog
https://posthog.com/
- Analyst reference target: analytics controls, explicit query context and links between charts and investigation.
- Separate its expressive marketing identity from its operational analytics interface.

## Shopify Admin
https://help.shopify.com/en/manual/products
- Analyst recommendation: study how catalog lists connect individual-record actions with bulk management, rather than building separate, inconsistent workflows.
- Keep filters, selection, bulk actions and record details visually coordinated.
- Official documentation verifies product organization and bulk management. Exact current interface measurements and comparative visual superiority remain unverified.
- Source: https://help.shopify.com/en/manual/products

## Airtable Interfaces
https://www.airtable.com/platform/interface-designer
- Choose a layout around the workflow: list, kanban, calendar, timeline or dashboard, rather than forcing every task into the same card grid.
- Connect dashboard summaries to underlying records through drill-down.
- Analyst recommendation: borrow the relationship between overview and investigation, not the product's branding.
- Sources: https://support.airtable.com/v1/docs/adding-layouts-to-interfaces https://support.airtable.com/articles/5415824889-airtable-interface-layout-dashboard

## Asana
https://help.asana.com/s/article/create-projects-in-asana?language=en-US
- Show alternate views of the same work rather than duplicating information across unrelated screens.
- Use list views for task details, calendars for timing and timelines for dependencies.
- Analyst recommendation: keep view switching near the object or project title, with a clear selected state.
- Source: https://help.asana.com/s/article/create-projects-in-asana?language=en-US
