# Choose one useful map

Load only when mapping resolves a current decision or is requested. An unframed idea still follows shared intake before maps. Skip mapping for clear corrections or a sufficient existing map. Choose one smallest useful map; do not generate every map automatically. A short table or prose can be enough; do not default to diagrams or new documents.

| Decision | Map | Boundary |
| --- | --- | --- |
| Understand one actor's goal and experience over time | User journey | Sourced scenario, stages, actions, channels and pain points; emotions only if supplied. |
| Clarify actions and branches for one user goal | Task flow | Entry, decisions, outcome, interruption, exit, return and recovery. |
| Organize where content or destinations live | Navigation structure | Reuse Phase 3 information architecture; a menu is not a task sequence or access control. |
| Explain known automatic work and state changes | System process | Sourced triggers, inputs, outputs, dependencies and limits; not imagined implementation. |
| Connect an actor's experience to service delivery | Service blueprint | Visible frontstage, known backstage, support and human handoffs for one scenario. |

Choose by the unanswered decision, not the requested diagram vocabulary. Briefly explain a mismatch and deliver the useful map within authority. Do not manufacture more layers to appear comprehensive. For another perspective, separate it only when needed; do not combine multiple actors into one factual journey. If supplied evidence supports only part of a map, label its gaps rather than filling them.

## Establish the map's basis

Name the sourced actor, goal/scenario, current phase, boundaries and relevant record IDs/date/version. Keep current-state evidence separate from future-state proposals. Label Observed, Reported, Inferred, Hypothesis and Unknown using Phase 1 evidence guidance when claims need interpretation. A current map can include reported behavior without calling it observed. A future proposal must be grounded in authorized goals and labeled Proposed; it is not a finding, current capability or approved implementation.

Never invent emotions, teams, channels, dependencies or business processes. Missing facts stay Unknown or are omitted when immaterial. Do not invent personas, quotes, patterns, confidence or validation. Preserve contradictory evidence and positive outcomes, not just friction. Keep source/sample/confidence basis/limits available behind the summary, using optional synthesis when supplied records need grouping. A method guide is guidance, not product evidence.

Retain every supplied accessibility or safety issue even without repetition. Preserve interruption, return and recovery issues and unresolved consequences; their absence from a happy path is not evidence they are harmless. No map establishes accessibility, security, safety, service reliability or usability Pass. Reuse shared authority, evidence and readiness rules; hidden navigation never establishes access control.

Work mostly behind the scenes. Show the selected map only if useful/requested; otherwise concise findings, risks, missing decisions and one recommended next step. Do not jump from a map into screens, new scope, workshops or a document set. Mapping does not authorize recruitment, messages, recording, payment or deployment.
