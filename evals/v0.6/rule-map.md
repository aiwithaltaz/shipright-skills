# Rule changes in 0.6

This map explains compression without claiming that every old instruction was correct. Paths are relative to the pack. No original file was renamed or deleted.

| Intent | Current owner | Treatment |
| --- | --- | --- |
| Outcome, useful mechanism, objects, journey and screen jobs | skills/product-design/SKILL.md and decision-checklist.md | Retained; removed fixed object counts and mandatory three-approach ceremony. |
| Decision ownership, source, approval and changing requirements | skills/_shared/operating-contract.md | Retained; reuse explicit authorization and update affected dependent work. |
| Current scope and exact corrections | Shared operating contract; requirements-and-feedback.md | Strengthened to current-phase sources and keep/remove/change/add acceptance checks. |
| Light intake and delegation | skills/_shared/intake.md | One 0-5 total budget before work. Usually three for a vague idea, zero for a clear fix. No repeated questionnaires. |
| Exit, consistency, status and severity | skills/_shared/flow-rules.md | One canonical source and two compact checked exports. Removed legal/payment traps and mandatory routine plumbing. |
| Entry, return visits, dependencies, money and related records | product-design references | Retained as conditional lenses, never a reason to add those features. |
| Layout, hierarchy, icons and placement | ui-ux-design references | Retained and made concrete for reading order, sizing, responsive behavior, profile home and distinct selection/focus/unread states. |
| Empty/error/loading and unfinished work | states-and-flows.md; state-coverage.md | Retained; separate saved human work from background execution, and clearing selection from deleting data. |
| Existing identity and design systems | references-and-design-system.md; existing-app.md | Preserve/Establish retained; facts, observations, proposals and delegated choices are distinct. |
| Motion, copy and anti-slop checks | ui-ux-design references | Retained conditionally. Removed universal style bans, numerical quotas and mandatory counting output. |
| Accessibility and difficult content | state-coverage.md | Strengthened with measurable criteria, semantics and runtime evidence limits. |
| Research and product hypotheses | opportunity-research.md | Retained as a requested/agreed stage with sources; never invented validation. |
| Project files and portable handoff | output-folder.md; doc-set.md; docs/ | Retained; corrected app-root paths. Removed stops between already-authorized files and fixed example roles. |
| Critique, stage readiness and bounded verification | Shared contract; ux-critique references | Retained. Separate specification, visual and runtime proof. Optional check limits never excuse leaving a required fix unfinished. |
| Launch review and 20 stable items | ship-check and docs/ship-check.md | Retained; product-critical checks still apply outside the list. One four-status vocabulary. |
| Personal preferences | personal-taste/ | Still opt-in. Existing spacing and brand systems outrank a profile default. |
| Historical examples and evidence | examples/ and evals/ | Retained with defect notices. Three training candidates now mark unsupported policy as proposed or unknown. |

Removed repeated progress/rephrase instructions, forced global action/layout rules, automatic broad audits for small corrections, unnecessary document output and unconditional sensitive-search URLs. Their useful intent remains: communicate clearly, keep consistency by context, check affected behavior, preserve work and protect private input.

The four entry files retain a compact fallback for incomplete installations. This small repeated safety summary is deliberate; it explicitly says a partial pack cannot perform a full ShipRight check.
