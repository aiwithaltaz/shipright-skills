Case study · Habit tracker phone app

Same prompt, twice.
One with ShipRight 1.6.

We built the same habit tracker with the same prompt in Grok Build (Grok 4.7). Once without ShipRight (it named itself Daymark), once with ShipRight 1.6 (it named itself Nock). Open both on your phone.

Try without ↗ Try with ShipRight ↗

The screens

What you see on your phone.

The prompt asked for a private habit tracker: mark today, add a habit, see streaks and the week. Nothing else changed between the two runs.

Why

Six decisions ShipRight made.

Each quote is from the PRODUCT.md and DESIGN.md that ShipRight 1.6 wrote before any code.

  1. 01

    Today first, one tap.

    The plan put today on the first screen, with the open count as the heading and a labeled button on each habit. The plain build shows the date, a big sample banner, and an empty circle you have to guess is the button.

    “First screen for the main user: today's habits, each with a Notch or Done control. The heading states how many are still open.”

    PRODUCT.md
  2. 02

    A streak that does not erase your effort.

    Research found that Streaks resets a habit to zero after one miss, and people feel the past effort disappeared. So each habit carries a 4-week tally stick: a slash for done, a red tick for a miss, a yellow line for today.

    “They get anxious when a counter snaps back to zero.”

    PRODUCT.md
  3. 03

    References of the same type, and a test against the AI look.

    It picked three habit and today-list apps: Streaks, Things 3 and Loop Habit Tracker. Then it checked that the look was not the default AI look. The plain build landed on exactly that look: cream page, serif headline.

    “A cream page, a high-contrast serif, and a terracotta accent would look like any other generated app.”

    DESIGN.md
  4. 04

    A mood from the product's own world.

    The mood is a pocket index card and a navy ballpoint. The red line is the card's margin rule. On a wide screen it opens like a notebook: today on the left page, this week on the right.

    “Index card, ballpoint, notch.”

    DESIGN.md
    • Paper #E6EDF1
    • Ballpoint #143049
    • Margin #9E2218
    • Pencil #C8962E
  5. 05

    The main jobs in a few taps.

    Mark today, undo it, add a habit, and look at the week. Status text sits in the page and confirms each change. This clip is the real app: Notch, then Add a habit, then This week.

    “See today's due habits and mark one done, or undo that mark, in one tap.”

    PRODUCT.md
  6. 06

    Every state planned.

    Before any screen, the plan listed what each page shows when empty, when storage fails, and with long names. Both apps handle the empty state. Nock also explains a blocked browser without deleting anything.

    “Storage blocked, or the save could not be read. Try again. Overwrite only after a confirm.”

    PRODUCT.md

We graded both ourselves. It was not blind. The plain build looks more polished at a glance; the ShipRight build is more its own and clearer about the job. Open both and judge.

What is still weak in the ShipRight build

  • The phone page is long and has a lot of small explaining text.
  • A finished habit shows a filled dark Done button, so it looks like the main action.
  • The last Today status line still shows on the Add a habit screen.
  • When storage is blocked it stops, though its own DESIGN.md says you can still try the sample.
  • "Notch" is a new word you have to learn.
