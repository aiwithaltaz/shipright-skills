# Skills catalog

**ShipRight 1.4.0**

Install one skill: [shipright](skills/shipright/SKILL.md). The rows below are its modes. A new idea starts at [Research](skills/shipright/stages/01-research.md), even when the request says to just build it. Naming build-pack still runs stages 1 to 10. An existing app starts at [Discover](skills/shipright/stages/00-discover.md).

| Request | Skill | Review size |
| --- | --- | --- |
| Idea to build: PRD, stack, design system, screens and ticket prompts | [build-pack](skills/shipright/modes/build-pack/MODE.md) | 10 checks before the reply |
| Public website or immersive page | build-pack within the same five modes | Product brief, six acts, three story options, longer prompt, taste critique |
| Rough idea, outcome or flow decision | [product-design](skills/shipright/modes/product-design/MODE.md) | 8 checks at handoff |
| Supplied research synthesis and product decisions | product-design | Optional evidence-linked findings, risks and proposed decisions |
| Approved product organization, navigation, findability or route maps | product-design | Optional sourced structure and decisions before screens |
| Journey, task/system flow or service delivery decision | product-design | Optional one sourced map, risks and proposed decisions |
| Research evidence, method or lightweight study plan | product-design | Decision-relevant evidence/plan, not invented validation |
| Screen layout, system or exact correction | [ui-ux-design](skills/shipright/modes/ui-ux-design/MODE.md) | 10 checks at handoff |
| Existing system selection, foundations or maintenance | ui-ux-design | Small system before screens: Observed reuse, or Proposed until the user agrees. Vocabulary, control choice and reference systems load only when needed |
| Artifact review or plan score | [ux-critique](skills/shipright/modes/ux-critique/MODE.md) | 10 checks when relevant |
| Full launch review | [ship-check](skills/shipright/modes/ship-check/MODE.md) | 20 items plus product-critical requirements |
| One release item | ship-check | That item and direct dependencies |
| Requested document set | build-pack for the full set; product-design for single documents | Only requested files |

Existing apps do not always need a full audit. Route an explicit correction directly to the relevant skill.
Start with current instructions and relevant artifacts. Apply [shared intake](skills/shipright/modes/_shared/intake.md) once, across skill boundaries.
Use [the operating contract](skills/shipright/modes/_shared/operating-contract.md) for exact feedback, phase scope, facts and evidence.

New product work connects outcome, useful mechanism, objects, journey, screen jobs, UI and handoff.
Do not force every task through that whole sequence. Inspect supplied evidence quietly; use bounded research when authorized and decision-relevant.
Broad market research remains requested/agreed. Missing research permits labeled hypotheses, not invented facts.
Existing-product work inspects affected context, preserves what works, makes authorized changes and verifies the affected result.

Load only the references named for the current task in its MODE.md. Do not load all examples, templates or historical evals by default.
Use [Flow rules (must pass)](skills/shipright/modes/_shared/flow-rules.md) for F1 exit, F2 consistency and F3 useful status.
Profiles are [opt-in](personal-taste/README.md). Requested output paths are defined in [output-folder.md](skills/shipright/modes/_shared/output-folder.md).
